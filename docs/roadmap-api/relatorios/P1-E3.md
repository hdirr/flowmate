# P1-E3 — `POST /v1/contacts/{id}/tags`

**Status:** pronto · **Commit:** `efefd45` — feat(P1-E3): POST /v1/contacts/{id}/tags · **SQL:** não se aplica
**Processo:** simplificado (bloco do tester).

## O que mudou
- **`api/_lib/v1/contacts.js`, `updateContactTags`:** operações `InsertIfNotExists` (padrão),
  `DeleteIfExists` e `ReplaceAll`, com os nomes da Helena.
  - **Entrada:** 1 a 50 tags, de até 100 caracteres. Espaços das pontas são removidos e
    duplicatas da entrada são ignoradas. Lista vazia só com `ReplaceAll`.
  - **Comparação exata, que diferencia maiúsculas**, como o filtro `tag` da L4.
  - **Ordem:** a das tags atuais é mantida; as novas entram no fim.
  - **`added`/`removed`** são a diferença real. Nada mudou → 200 sem update e sem evento.
  - **Erros:**
    - 400 `invalid_tags` / `invalid_operation` / `invalid_body`;
    - 404 `contact_not_found` (inexistente, de outra empresa, id que não é UUID).
  - **Evento:** `contact.tags_updated` `{ contact_id, tags, added, removed, source: "api" }`,
    dentro de `try/catch`.
- **`api/_lib/events.js`:** `contact.tags_updated` passou a `available: true`.
- **`router.js`:** rota `POST contacts/:id/tags`.
- **Contrato:** regras, erros e a limitação da automação "tag adicionada", que não dispara pela
  API.

## Perguntas / pendências
1. **Diferença de maiúsculas:** a tela grava a tag como o usuário digitou. Se o n8n mandar
   `VIP` e a tela tiver `vip`, ficam duas tags. Vale normalizar (por exemplo, minúsculas) numa
   etapa futura? Hoje seguimos o comportamento da tela e do filtro da L4.
2. **Eventos não conferidos no receptor** (webhook.site do Agadir): 3 `contact.tags_updated`
   entre 04:57 e 04:58 UTC de 02/10.
