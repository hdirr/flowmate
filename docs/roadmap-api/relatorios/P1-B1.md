## O que foi feito
- `api/_lib/v1/http.js` (novo):
  - `fail(res, status, error, message)` → `{ error, message }`.
  - `readPaging(query)` → `{ pageNumber, pageSize, from, to }`:
    - aceita o parâmetro em qualquer caixa (`pageNumber`, `PageNumber`, `pagenumber`);
    - `pageNumber` ≥ 1, padrão 1;
    - `pageSize` de 1 a 100, padrão 20; acima de 100 vira 100, sem erro;
    - valor inválido ou menor que 1 cai no padrão.
  - `paged(res, { pageNumber, pageSize }, items, totalItems)` →
    `{ pageNumber, pageSize, totalPages, totalItems, hasMorePages, items }`.
  - `readDate(query, name)`:
    - devolve ISO, ou `null` se o parâmetro estiver ausente;
    - data inválida lança `V1Error(400, 'invalid_date')`.
  - `isUuid(value)` → boolean.
  - `V1Error`: erro que um handler novo pode lançar; o roteador converte em `fail()`.
- `api/_lib/v1/router.js` (novo):
  - `ROUTES = []`, vazia nesta tarefa;
  - `match(method, route)` devolve:
    - `{ handler, params }` quando caminho e método casam;
    - `{ methodNotAllowed: true, allow }` quando o caminho existe com outro método (405);
    - `null` quando nada casa e a requisição segue para o switch antigo;
  - os parâmetros `:id` são decodificados; `%` quebrado conta como "não casa", em vez de dar 500.
- `api/_lib/events.js` (novo): `WEBHOOK_EVENTS` exatamente como no `12` (5 da v1 + 6 da Parte 1,
  cada um com `event`, `description` e `since`).
- `api/v1/[...path].js`:
  - mantido o fallback que deriva a rota de `req.url`;
  - ordem de resolução: primeiro `match()` na tabela nova (hoje vazia); se nada casar, o
    `switch` antigo, **sem nenhuma alteração**;
  - quando uma rota nova casar com o método errado: `405 { error: 'method_not_allowed', message }`;
  - um `V1Error` lançado por handler novo vira `fail()`; outros erros sobem como antes;
  - rota não encontrada continua `404 { error: 'not_found', route }` (vem do switch antigo);
  - CORS: `PUT` e `DELETE` acrescentados em `Allow-Methods` e `Authorization` em
    `Allow-Headers`; o `OPTIONS` continua 204;
  - leitura da chave não mudou (fica para a P1-B2).
- Não foram alterados `api/_lib/v1handlers.js`, as rotas de `contacts` (as exceções ficam para
  a P1-L4 e a P1-E2) nem o número de funções (arquivos novos só dentro de `api/_lib/`).
