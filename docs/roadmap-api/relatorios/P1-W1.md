# P1-W1 — Evento `conversation.state_changed`

**Status:** pronto no código; **testes de tela e celular aguardam o Agadir** (roteiro abaixo)
**Commit:** `5a1f82a` — feat(P1-W1): evento conversation.state_changed · **SQL:** não se aplica
**Processo:** simplificado (bloco seguinte ao do tester).

## O que mudou
- **`api/_lib/conversations.js`:**
  - assinatura nova, compatível com as chamadas atuais:
    `setConversationState(conversationId, state, actorUserId = null, source = null)`;
  - lê `company_id, contact_id, remote_jid, state` antes do update;
  - se o estado mudou de fato, dispara `conversation.state_changed`
    `{ conversation_id, contact_id, remote_jid, state, previous_state, changed_by, user_id }`;
  - **`changed_by = source || (actorUserId ? 'user' : 'phone')`**;
  - o dispatch fica em `try/catch` e com **limite de 3 s** (`Promise.race`): esta função também
    roda no fluxo de mensagens do webhook da Evolution (dono respondeu pelo celular), e um
    webhook lento do cliente não pode segurar esse fluxo.
- **`api/conversations/state.js`** (botão "pausar"/"devolver" da tela): passa `source = 'user'`.
  Sem isso, ao devolver para automação o `actorUserId` vai nulo e o evento sairia como `phone`.
- **`api/_lib/v1/conversations.js`** (P1-E6): passa `source = 'api'`.
- **`sendMessage.js` e `handleWebhook` não foram editados.** A regra deduz o valor certo:
  - envio pela tela → `user`, com o id do usuário;
  - resposta pelo celular → `phone`, sem usuário.
- **`api/_lib/events.js`:** `conversation.state_changed` passou a `available: true`.
- **Contrato:** linha do evento com o significado de `changed_by` e `user_id`; a seção da E6
  passou a citar o evento.
- **Coluna `state_by` não muda** (decisão do tutor): continua nula pela API e pelo celular. Quem
  distingue é o `changed_by` do evento.

| Caminho | `changed_by` | `user_id` |
| --- | --- | --- |
| Atendente envia pela tela (vira humano) | `user` | id do atendente |
| Botão "pausar" na tela | `user` | id do usuário |
| Botão "devolver para automação" | `user` | `null` |
| Dono responde pelo celular | `phone` | `null` |
| `PATCH /v1/conversations/{id}` | `api` | `null` |

## Roteiro para o Agadir (tela e celular)
Com o webhook.site aberto e todos os eventos desmarcados em Integrações:
1. **Tela, pausar:** no Chats, abra uma conversa **sua** de teste em automação e clique em pausar
   → `conversation.state_changed` com `changed_by: "user"` e o seu `user_id`.
2. **Tela, devolver:** clique em "devolver para automação" → `changed_by: "user"`,
   `user_id: null`.
3. **Tela, enviar:** com a conversa em automação, envie uma mensagem pelo Chats → vira `human`
   com `changed_by: "user"` e o seu `user_id` (além do `message.sent`).
4. **Celular:** devolva para automação; depois **responda pelo celular** nessa conversa →
   `changed_by: "phone"`, `user_id: null`.
5. **Smoke 1.8 (obrigatório depois da W1):** mande uma mensagem de WhatsApp de outro aparelho
   para o número da empresa e confira que ela aparece no Chats em segundos.
6. Volte a conversa para automação no fim.
