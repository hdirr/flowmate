# P1-E5 — `POST /v1/leads/{id}/notes`

**Status:** pronto · **Commit:** `d7d69c3` — feat(P1-E5): POST /v1/leads/{id}/notes · **SQL:** não se aplica
**Processo:** simplificado.

## O que mudou
- **`api/_lib/v1/leads.js`, `createLeadNote`:** cria a nota em `crm_notes` no **contato** do
  lead (`auto: true`, como o `POST /v1/notes` antigo).
  - **`text`:** obrigatório, até 8000 caracteres → 400 `missing_text` / `text_too_long`.
  - **`user_id` opcional = autor.** Precisa ser um usuário da mesma empresa, senão 400
    `invalid_field`. Sem ele, `user_id: null`.
  - **Resposta:** 201 com o objeto **Nota**.
  - **Erros:**
    - lead inexistente, de outra empresa ou id que não é UUID → 404 `lead_not_found`;
    - lead sem contato → 422 `lead_without_contact`;
    - corpo que não é objeto → 400 `invalid_body`.
  - **Evento:** `note.created` `{ note_id, contact_id, lead_id, text, source: "api" }`, em
    `try/catch`.
- **`api/_lib/events.js`:** `note.created` passou a `available: true`.
- **`router.js`:** rota `POST leads/:id/notes`, ao lado do `GET` da L11.
- **Contrato:** regras, erros e evento.

## Como testei
- **Local:** 6 validações sem banco (não-UUID, sem `text`, `text` vazio, 8001 caracteres,
  `user_id` inválido, corpo array).
- **Produção** (`d7d69c3`), **só no lead do `smoke-001`**:

| Caso | Resultado |
| --- | --- |
| Sem autor | 201, `auto: true`, `user_id: null` |
| Com autor (`user_id` do admin, via `GET /v1/users`) | 201, `user_id` preenchido |
| `user_id` que não é da empresa | 400 `invalid_field` |
| Sem `text` | 400 `missing_text` |
| Lead inexistente / não-UUID | 404 `lead_not_found` |
| Sem chave | 401 |
| `GET /v1/leads/{smoke}/notes` depois | 4 notas, mais recente primeiro; a nova com autor preenchido |
| Smoke | idêntico ao anterior |

**Caso que sobrou da L11 (nota com autor no GET): coberto.** A nota criada com `user_id` sai no
`GET /v1/leads/{id}/notes` com o autor. Nota com autor criada **pela tela** continua sem dado
real (não precisa mais: o GET só repete o que está na coluna).
