## O que foi feito
- `api/_lib/v1/conversations.js`, handler `listConversationMessages`:
  - **Busca:** acha a conversa (`company_id` + id) e lista `whatsapp_messages` com o mesmo
    `company_id` e `remote_jid`, a mesma regra do `last_message` da P1-L7.
  - **Formato:** cada item usa o formatador `toMessage` da L7 (objeto **Mensagem**, com
    `message_type → type`).
  - **`order`:** `desc` (padrão) ou `asc`, lido sem diferenciar caixa no nome do parâmetro.
    Outro valor → 400 `invalid_filter`.
  - **Ordem:** `timestamp` e, no empate, `id`, sempre na mesma direção. Timestamp nulo vai para
    o fim.
  - **Paginação:** a de sempre; página além do fim → `items: []` com o total real.
  - **Erros:**
    - id que não é UUID → 404 `conversation_not_found`, sem ir ao banco;
    - id inexistente ou de outra empresa → 404 `conversation_not_found`;
    - erro de banco: log `[v1] conversation messages falhou` + 500 `internal_error`.
- `api/_lib/v1/router.js`: rota `GET conversations/:id/messages`.
- `20-contrato-api-v1.md`, seção da rota:
  - `order` inválido → 400;
  - desempate por `id`;
  - busca por `remote_jid`;
  - só 7 dias de mensagens: conversa parada há mais tempo devolve `items: []`;
  - casos do 404.
