## O que foi feito
- `api/integrations/emit.js` foi o único arquivo alterado; `src/lib/store.js` não mudou.
  - **Lista fechada** `contact.created`, `lead.created`, `lead.moved`. Qualquer outro evento
    responde `400 { error: 'event_not_allowed' }` e nada é enviado. O teste usa
    `hasOwnProperty`, então nomes como `__proto__` também são recusados.
  - **Do `data` do navegador só o id é usado.** O payload é montado no servidor com
    `adminClient()`, filtrando pelo `company_id` da sessão (`resolveUser`):
    - `contact.created`: `contact_id` → `crm_contacts` → `{ contact_id, name, phone, email }`;
    - `lead.created` e `lead.moved`: `lead_id` → `crm_leads` →
      `{ lead_id, stage_id, pipeline_id, contact_id }`.
  - **Id inválido:** ausente, fora do formato UUID, inexistente ou de outra empresa responde
    `404 { error: 'not_found' }` e nada é enviado. Um id que não é UUID nem chega ao banco
    (regex antes da consulta), então nunca dá 500.
  - **Resposta de sucesso** continua `{ ok: true, ...result }`, igual à de antes. 401 sem sessão
    e 405 para outro método também não mudaram.

O `emitIntegration` do `store.js` roda **depois** do `await` do insert/update, então o servidor
lê o estado já gravado.
